# Plan: S3 Finish — Multi-category, Gallery images, Google Places Autocomplete

**Date:** 2026-06-09
**Slug:** 2026-06-09-s3-finish
**Status:** reviewed
**Author:** /mlabs-plan

---

## Problem

Sprint 3 is 80% done. Three features remain before S3 is shippable:

- **F13 multi-category attach** — businesses carry a single `category` text
  column. Admin can't tag a business as e.g. "Restaurants + Events". Users
  browsing either category miss the listing.
- **F10/F13 gallery images** — the detail page hero shows one `image_url`.
  Businesses with multiple photos (interior, exterior, menu) can't surface
  them. Admin has no upload UI.
- **F27 Google Places Autocomplete** — the address field is a plain text box.
  Admin spells the address wrong; geocoding and future directions deep-links
  break silently.

All three block S4 sign-off and the overall app store timeline.

---

## Scope

**In:**
- `business_category` join table (migration `0017`) — a business belongs to
  one primary category (existing `businesses.category` column, unchanged) plus
  zero or more additional categories from the join table.
- Admin `BusinessAdminDetail` → replace single `CategorySection` `<select>`
  with a multi-select that reflects the join table. Primary category stays the
  routing key; extras are stored in the join table only.
- Public `BusinessDetail` hero — display up to 3 gallery images in a simple
  tab/dot carousel when multiple images exist; fall back to single `image_url`
  hero when the gallery is empty.
- `business_image` table (migration `0017` same migration) — `id`, `business_id`
  FK, `url`, `sort_order`, `created_at`. Max 3 rows enforced at the service layer.
- `POST /api/v1/admin/businesses/[id]/images` upload route — multipart, reuses
  Sharp + Replit Object Storage pipeline from the avatar feature.
- `DELETE /api/v1/admin/businesses/[id]/images/[imageId]` remove route.
- Admin gallery section in `BusinessAdminDetail` — dropzone (react-dropzone),
  thumbnail strip, delete button per image, max-3 guard.
- `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` added to `env.ts` client block.
- Google Places Autocomplete on the admin Business address field (vanilla
  Places JS API, no heavy npm SDK). Replaces the plain `<Input>` in
  `CoreFieldsSection`.
- Validators, services, ops, routes all updated to carry `images: BusinessImage[]`
  alongside `Business`.

**Out (deferred):**
- F25 city-aware slugs (`/atlanta/restaurants/slug`) — separate plan.
- Lat/lng storage — address text is enough for MVP; geocoords deferred to S6.
- Public-facing category cross-listing pages ("also in Restaurants") — S4+.
- Gallery reorder drag-and-drop — sort_order is stored; drag UI deferred to S6 polish.
- CDN / image optimisation beyond Sharp resize — Replit Object Storage serves
  directly for MVP.

## Approach

### 1 — Multi-category (`business_category` join table)

Keep `businesses.category` as the **primary routing category** (unchanged
column, no migration cost, no routing breakage on `/listings/[slug]`).
Add a new `business_category` join table: `business_id` + `category_id` (FK
to `category.id` from the S2 schema). A business can appear in multiple
categories while still having one canonical URL.

Admin `CategorySection` in `business-detail.tsx`:
- Render the existing primary `<select>` (unchanged).
- Below it, render a multi-checkbox list of all active root categories from
  the same `categories` prop already passed to the page. Check = row in join
  table. Persist via `PATCH /api/v1/admin/businesses/[id]` extended to accept
  `extra_category_ids: string[]`. The route handler diffs and upserts/deletes
  join rows in one transaction.
- Public listing pages: `getBusinessesByCategoryPaged` gains an OR branch —
  match on `businesses.category = slug` OR `business_category.category_id IN
  (select id from category where slug = ?)`. Already paginated; no new route
  needed.

### 2 — Gallery images

**DB:** `business_image` table (in migration `0017` alongside
`business_category`): `id` (uuid PK), `business_id` (FK businesses.id, ON
DELETE CASCADE), `url` text, `sort_order` int (default 0), `created_at`.
Unique index on `(business_id, sort_order)`. Service enforces max-3 at
insert time (count before inserting).

**Upload pipeline:** copy/adapt `features/avatar/server/pipeline.ts`.
New file: `features/admin/server/business-image-pipeline.ts` —
`processAndStoreBusinessImage(args)` resizes to `1200 × 800` cover JPEG,
stores to Object Storage under `businesses/<businessId>/<uuid>.jpg`, inserts
the DB row.

**Routes:**
- `POST /api/v1/admin/businesses/[id]/images` — multipart, `requireAdminJSON`,
  calls pipeline. Returns `{ image: BusinessImage }`.
- `DELETE /api/v1/admin/businesses/[id]/images/[imageId]` — deletes DB row +
  best-effort storage delete (same pattern as avatar).

**Admin UI:** new `GallerySection` in `business-detail.tsx` — `react-dropzone`
accept zone (click or drag), thumbnail strip (3 slots), ✕ button per image,
disabled when count = 3.

**Public detail page carousel:** when `business.images.length > 1`, replace
the single `<img>` hero with a simple client component `BusinessImageCarousel`
— renders the images as a scrollable strip with dot indicators (CSS scroll-snap,
no JS carousel library). Single image keeps the existing `<img>` element.

**`Business` type extension:** `BusinessSchema` gains `images:
BusinessImageSchema[]` (default `[]`). All existing callers get the empty
array automatically; no breaking change.

### 3 — Google Places Autocomplete

**Env:** `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` added to the `client` block of
`env.ts`. Exposed via `NEXT_PUBLIC_` prefix so the client component can read
it directly. Not added to `runtimeEnv` raw `process.env` (uses the
`@t3-oss/env-nextjs` client block pattern). `.env.example` updated.

**Approach:** load the Places JS API via a `<Script>` tag in the admin layout
(`strategy="beforeInteractive"` scoped to admin). No npm SDK — the vanilla
`google.maps.places.Autocomplete` widget is all we need; it ships with the
API loader and avoids a 40 kB bundle hit.

**Component:** `PlacesAddressInput` client component in
`features/admin/components/`. Mounts the Autocomplete on a plain `<input>`,
listens to `place_changed`, extracts `formatted_address`, and syncs to React
state. Graceful degradation: if the API script hasn't loaded (slow network,
ad-blocker), the field behaves like a plain text input — no JS errors, just no
suggestions.

`CoreFieldsSection` in `business-detail.tsx` replaces the address `<Input>`
with `<PlacesAddressInput>`.

**Alternatives considered:**
- `@react-google-maps/api` npm SDK — rejected; adds ~40 kB, requires a context
  provider, overkill for one autocomplete field.
- `@googlemaps/js-api-loader` — reasonable but still an extra dep; vanilla
  `<Script>` achieves the same with zero cost.

## Data model changes

**Migration `0017`** (two tables in one file):

```sql
-- business_category join
CREATE TABLE business_category (
  id          TEXT PRIMARY KEY,
  business_id TEXT NOT NULL REFERENCES businesses(id) ON DELETE CASCADE,
  category_id TEXT NOT NULL REFERENCES category(id) ON DELETE CASCADE,
  created_at  TIMESTAMP NOT NULL DEFAULT NOW(),
  UNIQUE (business_id, category_id)
);
CREATE INDEX bc_business_idx ON business_category (business_id);
CREATE INDEX bc_category_idx ON business_category (category_id);

-- business_image gallery
CREATE TABLE business_image (
  id          TEXT PRIMARY KEY,
  business_id TEXT NOT NULL REFERENCES businesses(id) ON DELETE CASCADE,
  url         TEXT NOT NULL,
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  TIMESTAMP NOT NULL DEFAULT NOW()
);
CREATE INDEX bi_business_idx ON business_image (business_id);
CREATE UNIQUE INDEX bi_sort_idx ON business_image (business_id, sort_order);
```

**`businesses` table:** no column changes. `category` column stays.

**`BusinessSchema`** (`packages/validators/src/businesses.ts`): add
`images: BusinessImageSchema[]` (default `[]`).

**`BusinessImageSchema`** (new): `{ id, business_id, url, sort_order,
created_at }`.

**`env.ts` client block:** add `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY: z.string().optional()`.

## Edge cases

- **Max-3 gallery:** service checks `COUNT(*)` before insert and throws if
  already at 3. Route returns `400` with `images.limit_reached` code so the
  dropzone can show "Maximum 3 images reached" inline.
- **Cascade deletes:** `business_image` and `business_category` both have
  `ON DELETE CASCADE` on `business_id` — archiving/restoring a business leaves
  them intact (soft-delete only sets `deleted_at`); hard-purge (S5 cron) will
  cascade automatically.
- **sort_order collision:** unique index `(business_id, sort_order)`. Service
  assigns `MAX(sort_order) + 1` at insert; no concurrent insert risk in MVP
  (single admin actor).
- **Places API unavailable / ad-blocked:** `PlacesAddressInput` initialises the
  autocomplete in a `useEffect` wrapped in `try/catch`; falls back to plain
  text input — no error boundary needed.
- **`category` column vs join table divergence:** primary `category` column is
  the routing key. The join table holds extras. When admin changes the primary
  `<select>`, the route removes that slug from the join table extras if
  present (to avoid duplicates in queries).
- **Existing businesses with no join rows:** `Business.images` defaults to `[]`;
  `Business.extra_category_ids` defaults to `[]`. No backfill needed.
- **Object Storage not configured:** `processAndStoreBusinessImage` checks
  `REPLIT_OBJECT_STORAGE_BUCKET_ID`; if unset, throws `images.storage_not_configured`
  so the route returns a clear `503` instead of a cryptic crash.

## Acceptance criteria

### Multi-category
- [ ] Admin can assign a business to 1–N additional categories via checkboxes in `CategorySection`
- [ ] Browsing `/listings/restaurants` shows a business whose primary category is `events-entertainment` but has `restaurants` as an extra category
- [ ] Removing all extras leaves the business visible only under its primary category
- [ ] `business_category` rows cascade-delete when a business is hard-deleted

### Gallery
- [ ] Admin can upload up to 3 images via drag-and-drop or click; 4th upload is blocked with a clear message
- [ ] Each uploaded image is resized to 1200×800, stored in Object Storage, and displayed as a thumbnail in the admin form
- [ ] Admin can delete a gallery image; it is removed from both DB and Object Storage
- [ ] Public detail page shows a scrollable carousel with dot indicators when 2–3 images exist
- [ ] Public detail page falls back to single hero `<img>` when only `image_url` is set and gallery is empty

### Google Places
- [ ] Address field in admin Business form shows autocomplete suggestions as the admin types
- [ ] Selecting a suggestion fills the address field with the formatted address
- [ ] If the Places API fails to load, the field still accepts manual text input without errors

## Open questions

1. **Gallery image dimensions:** 1200×800 cover is assumed. Should portrait
   images use a different fit (e.g. `contain` with letterbox) or always crop to
   landscape?
2. **Primary category in join table:** should the primary `category` slug also
   be mirrored as a row in `business_category` for query simplicity, or kept
   separate to avoid double-counting? (Plan assumes separate — join table =
   extras only.)
3. **Places API key restriction:** the `NEXT_PUBLIC_` key will appear in the
   browser. Confirm the GCP key is restricted to HTTP referrers
   (`*.replit.dev`, `airabynisarga.com`) before this ships to production.
4. **Image storage path:** `businesses/<businessId>/<uuid>.jpg` — is this the
   right structure, or should it mirror the avatar path pattern
   (`avatars/<userId>.jpg`)?
