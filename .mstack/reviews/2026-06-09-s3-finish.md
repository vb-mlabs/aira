## Summary

Plan is approved with four corrections and five decisions locked. The data
model (two new tables in one migration), the primary-category-stays-as-routing-key
approach, the avatar-pipeline reuse for gallery images, and the vanilla Places
JS API strategy are all sound. Key corrections: (1) `strategy="beforeInteractive"`
on the Places `<Script>` would run before hydration — must use `"afterInteractive"`;
(2) `PlacesAddressInput` must render with identical styling to the existing
`<Input>` component; (3) two new npm deps approved (`react-dropzone`,
`@types/google.maps`); (4) `extra_category_ids: string[]` confirmed on
`BusinessSchema` with default `[]`, populated by JOIN. The GCP key restriction
requirement is captured as a **Pause if** on Task 6.

## Findings

### Blockers (fixed in this review)

- **Wrong Script strategy.** Plan specified `strategy="beforeInteractive"` for
  the Places JS API — this runs before Next.js hydration and is reserved for
  critical polyfills. The Places API widget attaches to a mounted DOM node, so
  it must load after hydration. **Fix:** use `strategy="afterInteractive"`.
  `PlacesAddressInput` must guard `useEffect` with a `window.google?.maps`
  check and retry or degrade gracefully if the script hasn't resolved yet.

- **PlacesAddressInput styling mismatch.** Plan said "mounts the autocomplete
  on a plain `<input>`" — but all other form inputs use `<Input>` from
  `@aira/ui-web/input`. The underlying `<input>` rendered by `<Input>` is what
  the autocomplete binds to. **Fix:** `PlacesAddressInput` accepts `value` /
  `onChange` props and renders `<Input>` (from `@aira/ui-web/input`) as its
  visible element; the `google.maps.places.Autocomplete` instance is attached
  to the ref of that `<Input>`'s inner `<input>` element.

- **Missing `@types/google.maps` dep.** Vanilla Places JS API access via
  `window.google.maps.*` has no TypeScript types without this devDep. Without
  it `tsc --noEmit` will fail. **Fix:** `pnpm --filter @aira/web add -D @types/google.maps`.

### Concerns (raised, decided, recorded)

- **Concern:** `react-dropzone` is a new runtime dep for `apps/web` (not in
  the existing `package.json`).
  **Decision:** Approved. No alternative meets click+drag+MIME-filter in fewer
  lines; it's a mature package with no transitive dep bloat.

- **Concern:** `extra_category_ids` on `BusinessSchema` means every public
  list/detail response includes the join-table IDs, even for public-facing
  Mobile API calls.
  **Decision:** Accepted. Default `[]` so existing callers are unaffected.
  Mobile can ignore the field for MVP; it will be useful later for "also in"
  category chips. The alternative (separate admin fetch) adds a waterfall.

- **Concern:** `businesses.category` (primary, text slug) and
  `business_category.category_id` (UUID FK) are different types. The query OR
  branch must subquery: `category_id IN (SELECT id FROM category WHERE slug =
  ? AND city_id = ?)`. The city-scoping clause is required because category
  slugs are unique per-city (unique index is on `(city_id, slug)`).
  **Decision:** Accepted. The subquery is cheap (indexed on city+slug);
  recorded in the implementation so `/mlabs-code` doesn't forget the city_id
  filter.

- **Concern:** `sort_order` unique index `(business_id, sort_order)` uses
  `MAX(sort_order) + 1` at insert. After a delete, gaps exist
  (e.g. orders 0, 2 after deleting 1). The unique constraint still holds;
  carousel order is preserved. Re-compaction not needed for MVP.
  **Decision:** Accepted as-is. Gaps are harmless.

- **Concern:** Storage key for business images must be parseable back to a key
  for deletion, same as avatars. The avatar pipeline uses
  `avatarKeyFromUrl(url)` which strips the `/api/storage/` prefix. Business
  images must follow the same prefix convention.
  **Decision:** `business-image-pipeline.ts` exports a `businessImageKeyFromUrl(url)`
  helper that mirrors the avatar pattern; the DELETE route uses it.

### Suggestions (taken or deferred)

- **Taken:** Image storage path locked as `businesses/<businessId>/<uuid>.jpg`
  (consistent with the `avatars/<userId>-<timestamp>.jpg` pattern; uuid is
  already unique so no timestamp needed).
- **Taken:** Open question 2 (join table vs primary column) — keep separate.
  Join table = extras only; no backfill; no double-counting in query.
- **Deferred:** Gallery reorder drag-and-drop (sort_order stored in DB, UI
  deferred to S6 polish per plan scope).

## Decisions locked

1. **`extra_category_ids: string[]`** added to `BusinessSchema` (default `[]`).
   Also added to `BusinessUpdateInputSchema` (optional, strict schema extended).
2. **Image dimensions:** 1200×800 cover JPEG. Portrait images cropped to
   landscape — uniform carousel height. No letterbox.
3. **Image storage path:** `businesses/<businessId>/<uuid>.jpg`.
4. **Join table = extras only.** `businesses.category` remains the sole routing
   key. When admin changes primary category, the route deletes any matching
   extra row from `business_category` to avoid duplicates.
5. **GCP API key must be HTTP-referrer-restricted** to `*.replit.dev` and
   `airabynisarga.com` before any production deploy. Captured as **Pause if**
   on Task 6.
6. **Script strategy:** `strategy="afterInteractive"` for the Places JS API
   `<Script>` tag in the admin layout.
7. **City ID in OR query:** the `business_category` subquery must include
   `city_id` when looking up a category by slug (unique index is per-city).
   `/mlabs-code` must thread `city_id` through — use the Atlanta city ID from
   the seed (or look it up from the active city). For MVP, query
   `WHERE slug = ? AND active = true` to find the category, then use its
   `city_id`-scoped lookup. Simplest: look up `category.id WHERE slug = ?`
   (slug is unique globally within a city; for MVP there's one city so a plain
   `WHERE slug = ?` LIMIT 1 is safe).

## Implementation plan

### Task 1: DB schema — `business_category` + `business_image` tables + migration

- **Files:**
  - `packages/db/src/schema/business-categories.ts` (new)
  - `packages/db/src/schema/business-images.ts` (new)
  - `packages/db/src/schema/index.ts` (edit — export both)
  - `packages/db/drizzle/migrations/0017_*.sql` (generated — `pnpm db:generate`)
- **What:** Define two Drizzle tables. `business_category`: `id` text PK,
  `business_id` FK → `businesses.id` ON DELETE CASCADE, `category_id` FK →
  `category.id` ON DELETE CASCADE, `created_at`, UNIQUE `(business_id,
  category_id)`. `business_image`: `id` text PK, `business_id` FK ON DELETE
  CASCADE, `url` text NOT NULL, `sort_order` int default 0, `created_at`,
  UNIQUE `(business_id, sort_order)`. Run `pnpm db:generate` then
  `pnpm db:migrate`.
- **Acceptance:** `pnpm db:generate` produces `0017_*.sql` containing both
  CREATE TABLE statements. `pnpm db:migrate` applies cleanly. `pnpm typecheck`
  passes.
- **Pause if:** migration would require dropping or altering an existing column.

### Task 2: Validators — `BusinessImageSchema` + widen `BusinessSchema` + `BusinessUpdateInputSchema`

- **Files:**

  - `packages/validators/src/businesses.ts` (edit)
- **What:** New file exports `BusinessImageSchema = z.object({ id, business_id,

### Task 3: Services — gallery image mutations + multi-category queries

- **Files:**
  - `packages/services/src/businesses/image-mutations.ts` (new)
  - `packages/services/src/businesses/queries.ts` (edit)
  - `packages/services/src/businesses/service.ts` (edit)
  - `packages/services/src/businesses/index.ts` (edit — export new mutations)
- **What:**
  - New `image-mutations.ts` (must `import "server-only"`): exports
    `addBusinessImage(db, businessId, url, sortOrder)` (checks count ≤ 3,
    throws `ApiError.badRequest("images.limit_reached", ...)` if at limit,
    inserts row), `removeBusinessImage(db, imageId)` (deletes row, returns
    deleted `url` for storage cleanup), `listBusinessImages(db, businessId)`
    (returns ordered array).
  - Edit `queries.ts`: `getBusinessById` and `getBusinessByIdIncludingArchived`
    add a second query for images (or LEFT JOIN) and attach `images[]`. Same
    for `getBusinessesByCategoryPaged` — images array per business, OR branch
    in WHERE clause: `eq(businesses.category, input.category)` OR
    `inArray(businessCategories.category_id, sql`(SELECT id FROM category WHERE slug = ${input.category} LIMIT 1)`)`.
    Also attach `extra_category_ids[]` from `business_category` join.
  - Edit `service.ts`: `updateBusiness` accepts `extra_category_ids?: string[]`
    — when provided, diffs against existing rows in `business_category` and
    runs inserts/deletes inside a `db.transaction()`. Also removes any extra
    row whose category_id matches the new primary `category` slug's id (to
    prevent duplicates).
- **Acceptance:** `pnpm typecheck` passes. A business fetched via
  `getBusinessById` has `images: []` and `extra_category_ids: []` (no
  regressions for existing rows).
- **Pause if:** The `db.transaction()` API differs from what you expect — check
  Drizzle v0.45 docs before writing the transaction; do NOT use raw
  `BEGIN/COMMIT` SQL.

### Task 4: Image upload pipeline + admin API routes

- **Files:**
  - `apps/web/src/features/admin/server/business-image-pipeline.ts` (new)
  - `apps/web/src/app/api/v1/admin/businesses/[id]/images/route.ts` (new)
  - `apps/web/src/app/api/v1/admin/businesses/[id]/images/[imageId]/route.ts` (new)
- **What:**
  - New pipeline (`import "server-only"`): `processAndStoreBusinessImage({ businessId, bytes, contentType })` — validates MIME (jpeg/png/webp), enforces 5 MB limit, Sharp-resizes to 1200×800 cover JPEG, uploads to Object Storage at key `businesses/<businessId>/<uuid>.jpg`, calls `addBusinessImage` service (may throw `images.limit_reached`). Returns `{ image: BusinessImage }`. Export `businessImageKeyFromUrl(url)` helper (strips `/api/storage/` prefix, mirrors avatar pattern).
  - POST route: `requireAdminJSON`, parse multipart, call pipeline, return `{ image }`.
  - DELETE route: `requireAdminJSON`, call `removeBusinessImage(db, imageId)` to get URL, call `businessImageKeyFromUrl` → `storage.delete` best-effort, return `{ ok: true }`.
- **Acceptance:** `pnpm typecheck` passes. POST to `/api/v1/admin/businesses/:id/images` with a valid JPEG returns `201 { image: { id, url, ... } }`. Posting a 4th image returns `400` with `code: "images.limit_reached"`. DELETE removes the DB row and attempts storage deletion.
- **Pause if:** `REPLIT_OBJECT_STORAGE_BUCKET_ID` is not set in the dev environment — surface a clear error rather than a silent crash.

### Task 6: Google Places Autocomplete

- **Files:**
  - `apps/web/src/config/env.ts` (edit)
  - `apps/web/.env.example` (edit)
  - `apps/web/src/app/admin/layout.tsx` (edit)

- **What:**
  - Install `@types/google.maps` as devDep: `pnpm --filter @aira/web add -D @types/google.maps`.
  - Add `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY: z.string().optional()` to `env.ts`

  - Add to admin layout just before `</div>`: `<Script src={\`https://maps.googleapis.com/maps/api/js?key=${env.NEXT_PUBLIC_GOOGLE_MAPS_API_KEY}&libraries=places\`} strategy="afterInteractive" />`. Guard: only render `<Script>` when the key is present (avoids broken script tag in dev without the key).

In `useEffect`, checks `window.google?.maps?.places` — if present, creates `Autocomplete` instance attached to the input's DOM node, listens to `place_changed`, calls `onChange(place.formatted_address ?? "")`. If not present (API not loaded / blocked), degrades silently to plain text input.
  - `CoreFieldsSection` in `business-detail.tsx` swaps the address `<Input>` for `<PlacesAddressInput>`.
- **Acceptance:** `pnpm typecheck` passes. Address field shows autocomplete dropdown when API key is set and a valid address is typed. Field accepts manual text entry when API is unavailable.
- **Pause if:** `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` is not set in Replit secrets — the `<Script>` tag must be conditionally suppressed (already handled by the guard above). **Also pause if** the GCP API key has NOT been restricted to HTTP referrers (`*.replit.dev`, `airabynisarga.com`) — do not ship this task to production without that restriction in place.
